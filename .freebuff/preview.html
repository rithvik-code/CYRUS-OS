CYRUS
An AI command layer that sits on top of your existing OS — not a new OS.
Palette (Ctrl+Space)  ·  Brain (Ollama, local & free)  ·  Locked-down hand (5 whitelisted actions)

Nothing skips a step. If intent parsing fails, CYRUS stops and tells you — it never retries with a "looser" interpretation.

The five MVP actions (on purpose, only five)

ActionExample phraseRisk
search_files"find my java assignments"LOW
open_app"open vs code"LOW
open_workspace"start my college workspace"LOW
move_file"move report.pdf to Documents/Work"MEDIUM · confirm
run_script"set up my python data science environment"MEDIUM · confirm

The model never executes raw commands — it can only emit one of the intents in actions.py, and hallucinated intents are rejected before anything runs.

Architecture

  • main.py — entry point; wires hotkey → pipeline
  • palette_ui.py — Tkinter palette + confirm dialog
  • intent.py — LLM call → validated JSON intent
  • permissions.py — readable static risk gate
  • actions.py — the security boundary (whitelist)
  • indexer.py — local semantic file index (MiniLM)
  • memory.py — SQLite transcript, always auditable
  • Local LLM: Ollama (qwen2.5:3b) — no key, offline
  • Cloud opt-in: only if CYRUS_CLOUD_KEY is set
  • Search: sentence-transformers all-MiniLM-L6-v2
  • Storage: SQLite — zero config, built into Python
  • UI: Tkinter — ships with Python
  • Sandbox: actions restricted to indexed_paths in config.yaml
  • Scripts: pre-registered only — the model picks, never writes shell

Run it

# 1. install deps
pip install -r requirements.txt

# 2. pull a local model (free, offline)
ollama pull qwen2.5:3b

# 3. launch
python -m cyrus.main

# press Ctrl+Space → "find my java assignments"

Tests: python -m pytest cyrus/tests/  ·  Config: cyrus/config.yaml declares everything the AI is allowed to touch. If it's not in the file, CYRUS cannot act on it.

Deliberate scope decisions

  • Not a kernel, not a distro, not a desktop environment replacement.
  • One local model is the default path — cloud is opt-in per env var, never required.
  • Filename + config-folder indexing in v1; content indexing is a real scope decision, not a checkbox.
  • Risk classification is a static table you can read top-to-bottom — more trustworthy than a black box for something with filesystem access.
  • Adding a sixth action is the wrong next step until these five feel reliable.
